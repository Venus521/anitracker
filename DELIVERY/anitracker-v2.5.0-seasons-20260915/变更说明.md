# 变更说明 · 追迹 v2.5.0（build 20260915c）· 2026-09-15

> 本轮两件事：① 季度切换重做成 B 站式（快、流畅、搜索里也有分季）；② Bangumi 相关同步功能整体摘除（先删，以后再说）。

## 一、Bangumi 同步摘除（BGMSYNC 开关）

**删除范围（用户可见层面全部消失）**

| 层面 | 摘除内容 |
|---|---|
| 详情页 | 「⟳ 拉取Bangumi进度」「↑ 推送Bangumi」两个按钮（DOM 移除） |
| 同步中心 | ① Bangumi 账号卡（绑定/更换 token/拉取全部/推送全部/完全对齐）整体不再渲染；中心介绍文案改为「账号云同步、本地备份与导入、其他平台导入」 |
| 自动行为 | 标记单集→自动推送、改状态/评分→推送：全部禁用（即使本地存有旧 token 也不发任何请求，回归 T15 已证） |
| 同步记录 | 「重试失败项 / 回滚本次」按钮不再出现；空态文案更新；历史记录保留可查 |

**明确保留（不是同步，是数据读取）**：免绑定搜索、在线添加自动拉全集、空条目一键补拉、关联 Bangumi（补剧集列表用，按钮文案已改）、整合季度、编辑集数、封面拉取。

**实现方式**：单一开关 `var BGMSYNC=false;`（index.html 头部）+ 8 个同步入口函数守卫 + `data-bgm-sync` 标记的按钮运行时移除。**恢复同步 = 把 false 改回 true，并把详情页按钮行里两个带 `data-bgm-sync="1"` 的按钮的该属性删除（或直接参考 backup_20260915_pre-v250 的 index.html）**，刷新即回。

**数据处置**：`at_bgm_token` / `at_bgm_un` 留存本机浏览器未删除（不发起任何请求）；历史同步台账完整保留可查；如想彻底清除凭据，浏览器 DevTools → Application → LocalStorage 删除这两个键即可。

## 二、季度切换重做（B 站式）

| 场景 | 旧行为（v2.4.4） | 新行为（v2.5.0） |
|---|---|---|
| 打开详情页 | 无季度条，需手动开「整合季度」面板等检索 | **自动整合**：后台检索同系列并生成季度条（结果缓存，下次秒出） |
| 切到已加入的季 | 秒切 | 秒切（不变） |
| 切到未加入的季 | **强制加入片单** + 现场拉两次接口（慢、且污染片单） | **预览模式**：有缓存秒开（实测 17ms），无缓存现拉一次并入缓存；顶部黄条「预览模式 · 未加入片单 ＋ 加入片单」，**显式点击才入库** |
| 预取 | 无 | 打开详情/完成整合/搜索加入后，后台按节流静默预取同系列各季剧集入缓存 |
| 搜索结果 | 平铺列表 | **同系列自动分组成「季度 chip」**（TV/第X季/剧场版/OVA，按季号排序），点 chip 添加即带整条季度条并触发预取（bgmAttachGroup） |

缓存：`at_series_cache`（parts ≤120 项 / eps ≤300 项，LRU 淘汰）；老友记 10 季、孤独摇滚全季均已真网实测（见验证记录）。

## 五、风险与注意

1. 搜索分季基于标题归一分组，个别别名差异大的系列可能分成两组（可手动整合季度合并）；不会产生错误数据，只影响展示分组。
2. 预取在打开详情时后台进行（每 350ms 一个请求、仅公开读接口），流量极小；断网时静默失败不影响使用。
3. 同步已删但 Bangumi 读取（搜索/剧集）依赖 api.bgm.tv 可达；断网时本地库/手动添加/缓存过的季度仍可用。
