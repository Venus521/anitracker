## 一、一句话结论

原来「注册」藏在登录表单下面一行小字「注册一个 →」里，点进去是个没有反馈、没有防重、刷新就丢的表单；
现在它和「登录」平级成两个 Tab，注册分「① 填邮箱密码 → ② 去邮箱收验证码」两步，发码有即时反馈、重复点击被拦、刷新回来还能接着填。

## 三、真正的缺陷修复（不是改文案，是改行为）

诊断阶段用真实浏览器打真实 CloudBase，拿到的是**实测数据**而非推测。以下 5 条全部有证据。

| # | 缺陷 | 证据 | 修法 |
|---|---|---|---|
| 1 | **可重复发信**。旧代码有 `if (btn.disabled) return;` 守卫，但 `btn.disabled` 在 `await signUp` 期间**从未被置 true** —— 守卫是死代码 | 实测 `signUp` 耗时 **5237 / 5802 ms**（真 SMTP 往返），这段时间按钮外观是「可用」的，连点就连发 | 点击瞬间**同步**置 `btn.disabled = true`（放在 `await` 之前），文案改「发送中…」，并加 `_sending` 模块级重入锁做第二道闸 |
| 2 | **刷新即丢验证凭证**。`verifyOtp` 句柄只存在模块级变量 `_pendingVerify` 里，是个**闭包**，没有明文可存 | 实测 `su.data.verification_id === undefined`，句柄只在闭包内捕获 `t.verification_id` | 用 `auth.resend({email, type:'signup'})` 取回 **`messageId`**（JWT，payload `{e, exp:+10min, pj}`），存入 `localStorage['at_reg_pending']`；刷新后用 **`auth.verifyOtp({token, messageId})`** 重建。凭证 10 分钟有效，本地留 9.5 分钟余量后丢弃 |
| 3 | **发信过程零反馈**。开始发码后界面毫无变化 | 实测 5 秒多的空窗期 | 加「发送中…」态 + 成功提示「验证码已发到 xxx，去邮箱看看（可能在垃圾箱）」+ 失败按错误类型给可读文案 |
| 4 | **「顺便设用户名」永远无效**。`#cbNewName` 在代码里**只被读过一次**（`querySelector('#cbNewName').value`），**从未被渲染** | `grep -c cbNewName` = 1，且那一处在 reader 里 | 真正渲染 `#cbNewName` 输入框（放进 `<details class="cbopt">` 折叠档），并抽出 `bindUsername()` 供注册时与登录后共用 |
| 5 | **错误文案靠撞中文，且会吐乱码**。旧 `errText` 靠 `helpMessage` 里的中文关键词命中 | 真实错误对象：`{category:'VERIFICATION_FAILED', errorCode:3, message:'无效的验证码%!(EXTRA string=rpc error: ...)'}` —— `%!(EXTRA …)` 是 **Go `fmt` 格式化残渣** | 改为**结构化字段优先**（`category` / `status` / `errorCode`），并用 `cleanMsg()` 砍掉 `%!` 之后的残渣，保证任何路径都不吐乱码 |

### 修复 #5 的一个关键细节（差点写错）

我第一版写成在 `VERIFICATION_FAILED` 分支里对**全字段拼接串**做 `/过期|失效|expire/` 匹配。
但实测的 `helpMessage` 是一份**「常见原因清单」**，里面**同时**列了「验证码已过期」和「验证码输入不正确」两条 —— 拿它匹配必然把**填错码**误判成**已过期**。
纯逻辑测试 `X1` 正是把这条抓出来的。

**正确写法**：只认 `message` / `status` / `error_description` 这三处**结论性**文本，不碰 `helpMessage`：

```js
if (cat === 'VERIFICATION_FAILED') {
  var concl = s + ' ' + c + ' ' + d;          /* 只有结论字段 */
  if (/expire|过期|失效/i.test(concl)) return '验证码已过期，请重新获取';
  return '验证码不正确，请检查后重填';
}
```

### 文案一致性

验证码文案从写死的「6 位验证码」改为 **4–8 位**，与 `finishSignUp` 的校验正则 `/^\d{4,8}$/` 统一（旧版提示与校验不一致）。

## 四、关键实现

### 4.1 凭证持久化（缺陷 #2 的修法）

```js
var LS_REG = 'at_reg_pending';

function saveRegPending(email, messageId){
  try {
    if (!email) { localStorage.removeItem(LS_REG); return; }
    localStorage.setItem(LS_REG, JSON.stringify({ email: email, messageId: messageId || '', at: Date.now() }));
  } catch (e) {}
}

function loadRegPending(){
  try {
    var p = JSON.parse(localStorage.getItem(LS_REG) || 'null');
    if (!p || !p.email || !p.at) return null;
    /* 验证码默认 10 分钟有效，留 30 秒余量；过期就丢掉 */
    if (Date.now() - p.at > 9.5 * 60 * 1000) { localStorage.removeItem(LS_REG); return null; }
    return p;
  } catch (e) { return null; }
}

function regResumable(){
  if (_pendingVerify || _pendingEmail) return true;   /* 内存里有闭包 */
  var p = loadRegPending();
  return !!(p && p.messageId);
}
```

`finishSignUp` 现在两条路都通 —— 有闭包走闭包，没闭包（刷新过）走重建：

```js
async function finishSignUp(verifyFn, code, username, email){
  var r;
  if (verifyFn) { r = await verifyFn({ token: code }); }
  else {
    var p = loadRegPending();
    if (!p || !p.messageId) throw new Error('验证凭证已失效，请重新点「获取验证码」');
    r = await auth.verifyOtp({ token: code, messageId: p.messageId });
  }
  if (r && r.error) throw r.error;
  var u = await sess();
  if (!u) throw new Error('验证成功但登录态没建立起来，请用邮箱 + 密码登录一次');
  var bound = '';
  if (username) { bound = await bindUsername(username); }
  clearRegPending();
  return { user: u, bound: bound };
}
```

## 七、已知遗留 / 下一步

1. **手机号 + 短信注册未做**。需先确认短信签名与模板报备，当前保持邮箱注册。
2. **顶栏 🎲「随机播放」按钮命名**仍待商定 —— 该功能实际是随机跳转详情，不涉及播放，与项目「纯记录工具」定位需再措辞。
3. **`resend` 的额外调用**：`startSignUp` 为了拿 `messageId` 多发一次 `resend`。实测 `resend` 返回的 `messageId` 与首次 `signUp` 同源，不影响用户收到哪封邮件，但严格说多了一次网络往返；若日后觉得没必要，可退回「不持久化、刷新即重发」。
4. **冷却倒计时**在切后台后依赖 `setInterval`，长时间后台可能不准；由于已有持久化凭证兜底，影响可接受。
