# AniTracker v2.10.0 交付说明 — 方向转向「账号」

日期：2026-09-25　版本：v2.10.0（build 20260925c）　上一版：v2.9.3

---

## 一句话

把压在「同步」这个词底下三件不相干的事拆开：**删掉 Bangumi 进度同步和 WebDAV 文件同步，把早已写好的邮箱账号系统扶正为右上角「账号」一级入口。**

---

## 为什么改

用户的诉求原话是：**「现有的全删，用最简单的登陆注册，但是我数据哪里保存」**。

排查发现，「同步」面板里其实混着三样东西：

| # | 是什么 | 判断 |
|---|---|---|
| ① | Bangumi 观看进度**双向同步**（拉取/推送/台账/回滚） | 删 —— 这是给「在 Bangumi 上也追番」的人用的；本作定位是纯记录 |
| ② | WebDAV **文件同步**（tracker-sync.json） | 删 —— 是账号系统的劣质代替品，还要用户自己搭 WebDAV；且密码用 `btoa` 明文存 localStorage，本身是安全隐患 |
| ③ | **账号云同步**（邮箱注册登录） | **扶正** —— 这才是「换设备接着看」的正解，而且早就写好了，只是被塞在默认折叠的档里 |

③ 的存在是本次最大的发现：`cloudbase-sync.js` 里邮箱+密码注册、邮箱验证码、用户名登录全都有，**不需要重做**。它只是被藏起来了 —— 这恰好又是 v2.9.1 被批评过的同一个毛病（"精简不是让你藏起来"）。

## 改了什么

### 新增：`openAccount()` 账号面板

面板结构（按使用频率排，账号第一屏）：

```
状态条         ● 已登录：xxx  /  ○ 未登录 · 片单只存在本机浏览器
账号卡（常开）  登录 / 注册（邮箱+密码 → 验证码 → 建号）
本地备份（常开）导出全部数据 / 导入数据（纯文件，不依赖账号）
高级设置（折叠）免绑定搜索 / 代理说明 / CORS 中继
```

顶栏入口按钮：**「⇅ 同步」→「☺ 账号」**（`aria-label` 同步改为"账号"）。

### 删除

**Bangumi 观看进度同步（33 个函数中的同步相关部分）**
`bgmPullShow` / `bgmPullProgress` / `bgmPushShow` / `bgmPushOneShow` / `bgmPullAll` / `bgmPushAll` / `bgmPushEp` / `bgmPushStatus` / `bgmSubjectBody` / `bgmEnsureSubject` / `bgmPatchEps` / `bgmRollback` / `bgmRetry` / `renderLedger` / `kindName` / `bgmLogAuto` / `syncLogAll`·`Save`·`New`·`Commit`·`Update` / `_lgDay` / `bgmUnboundHtml` / `bgmBoundHtml` / `bindBgmCard` / `rebind`

**WebDAV 文件同步**
`syncRun()` / `tracker-sync.json` 读写 / `tr_meta` 时间戳账本 / 6 分钟一次的后台 `setInterval` / WebDAV 配置面板与 `LS.cfg` 密码存储

**详情页按钮**：「⟳ 拉取Bangumi进度」「↑ 推送Bangumi」两个按钮移除。

**旧状态机**：`BGMSYNC` 开关、`syncOff`/`syncOffSet`、`syncFoldPref`、`syncHealth`、`at_sync_fold` 折叠偏好全部移除。

### 保留（重要边界）

**Bangumi 的「导入 / 关联」链路完整保留**：

`bgmSid` `bgmQueue` `bgmFetch` `bgmPullEpisodeList` `bgmFillEpisodes` `bgmAttach` `bgmAttachGroup`

它们也读同一个 token，但用途是**「把番和剧集列表填进片单」**，不是「同步观看进度」。删了会导致搜索添加、关联 Bangumi、来源校准全部失效。**这是「连代码一起删」最危险的地方 —— `bgm*` 前缀不能通配删。**

前端测试 `T10c` 专门守这条线。

## 顺带修掉的真 bug

**`CBSync.isOn` 未导出** —— `index.html` 里 `syncHealth()` 调用 `CBSync.isOn()`，但 `cloudbase-sync.js` 只导出了 `{mount, autosync, version}`。调用被 try/catch 吞掉，导致状态条**永远显示"云同步未开"**，静默失效。

修复：`cloudbase-sync.js` 补导出 `isOn()`（是否已登录且同步过）和 `current()`（取当前登录用户），新版 `acctStatus()` 用它们驱动状态条。

## 事故与恢复（必须记录）

用「区间删除」切 390 行时，**结束标记打错了位置**，把夹在中间的一批与同步无关的工具函数连带切掉：

`coverHealAll` / `editTotal` / `cacheCover` / `upHttps` / `coverNeedsHeal` / `coverCanAuto` / `coverMark` / `_cTry` / `_cTrySet` / `_searchCoverByTitle` / `healCoverFor` / `testMsgSetter`

回归测试 T20/T21/T24 立刻炸出 `ReferenceError: coverHealAll is not defined`，据此定位并全部按备份原样恢复。

**教训**：区间删除必须同时审计「被删区间内是否有非目标函数」。本次靠的是**改动前的完整备份 + 函数名集合 diff**（对比备份与新文件的 `function xxx(` 全集，逐个人工判断是否属于计划删除），恢复后 diff 结果为「非计划删除：无」。这个审计手段应固化为流程。
