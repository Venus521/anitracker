# 06 · 交接手册：账号模块（AniTracker 追迹）

> 接手人按本文可独立完成日常排查与应急处理。配套：《05-发布与回滚手册》《03-邮箱登录启用指引》。

## 1. 模块架构

```
追迹（单文件 PWA）
├─ index.html            主应用（含同步中心 UI；ani-tracker.html 为其字节一致副本）
├─ cloudbase-sync.js     账号云同步模块（渲染 #cbArea；注册/登录/上传/恢复/台账）
├─ tracker-sw.js         Service Worker（同源资源 network-first，更新即时可达）
└─ 本地数据：localStorage（业务数据 + at_sync_log 台账 + at_cb_last 上次上传时间）

CloudBase（腾讯云开发 · env: cloud1-d7gsn5t0w6407b963 · ap-shanghai）
├─ 认证：邮箱验证码注册/登录、用户名绑定、密码登录（须先启用「邮箱登录」）
└─ 数据库：集合 tracker_data → 每用户一条文档 u_<uid>（字段 ownerId / payload / updatedAt）
```

依赖：`static.cloudbase.net/cloudbase-js-sdk/3.7.0/cloudbase.full.js`（浏览器首次加载需联网）。

## 3. 数据流

1. **注册**：邮箱+密码 → `auth.signUp({email,password})` → 云端发验证码 → 用户填码 → `verifyOtp`
   → 建号并登录 →（可选）`currentUser.updateUsername(用户名)`。
2. **登录**：邮箱或用户名 + 密码 → `auth.signInWithPassword` → 会话（自动续期由 SDK 托管）。
3. **上传**：`立即上传` → 打包 localStorage → 写 `tracker_data/u_<uid>`（add 优先、冲突则 update）。
4. **恢复**：`从云端恢复` → 读取该文档 → 逐项写回 localStorage → 刷新。
5. **自动同步**：曾成功上传过（`at_cb_last` 存在）的账号，保存数据后 5 秒防抖自动上传。
6. **台账**：同步与账号行为（注册/登录/绑定/退出）均写入 `at_sync_log`（最多 80 条），同步中心可见。

## 4. 排障手册

| 症状 | 检查 | 处置 |
|---|---|---|
| 注册提示「云端还没开启邮箱登录」 | 控制台 登录方式 / SMTP | 按《03-邮箱登录启用指引》开启（2 步） |
| 收不到验证码 | ①SMTP 配置 ②垃圾箱 ③频率限制 | 重发（60 秒后）；换邮箱测试；检查发件箱 |
| 登录提示「邮箱/用户名或密码不正确」 | 账号是否存在 / 密码大小写 | 先注册；确认密码（8–32 位含字母数字） |
| 「绑定用户名」失败 | 用户名是否被占用 / 规则 | 换一个（字母数字或 -/_，非纯数字） |
| 上传失败 | 登录是否过期（退出重登） / 网络 | 重新登录后重试；断网时稍后自动重试 |
| 页面还是旧版 | 版本行（设置→底部或同步中心） | Ctrl+F5 强刷；或用「一键打开」脚本重开 |
| 手机与电脑数据不一致 | `at_cb_last` / 同步记录 | 在目标设备点「从云端恢复」 |
| 需要看失败明细 | 同步中心→同步记录 | 点标题展开；或导出 localStorage 的 `at_sync_log` |

node tests\run-regression.js     # 全量回归 19 项

## 5. 值守与变更纪律

- 当前责任人：**用户本人**（单人产品）；技术支持入口：本仓库维护者。
- 变更纪律（重要）：①改前备份（`backup_日期_说明/`）②本地双测全过 ③版本号三方一致（`AT_VERSION` = `tracker-version.json` = 测试断言）④运行 `同步双入口.py` ⑤留交付记录。
- 云侧变更：控制台登录方式/发件人配置变更后，跑一次 `account-live-verify.js`。
