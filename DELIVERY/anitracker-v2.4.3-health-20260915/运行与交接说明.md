## 二、启动与停止

**日常启动（推荐）**：双击 `D:\项目\01_媒体娱乐\ani-tracker\AniTracker追迹-一键打开.bat`

流程：① 检测 8089 端口 → ② 未在运行则后台起服（`server.py --port 8089 --host 0.0.0.0 --dir <项目目录> --idle 900`）→ ③ 等待就绪后打开 `http://127.0.0.1:8089/index.html?v=<随机数>`。

**停止**：
- 自动：服务在 **15 分钟**（900 秒）无请求后自动退出（设计行为，平时零驻留）；
- 手动：任务管理器结束对应 `pythonw.exe`（以 `服务器日志.txt` 中记录的进程为准，或任务管理器搜索 `pythonw`）。

**开机后第一次访问提示“连接被拒绝”？** 属正常——服务尚未启动。走上面“日常启动”即可（或等空闲自退机制重新起服）。

**手机/平板同网段访问**：`http://<本机局域网IP>:8089/index.html`（服务绑定 0.0.0.0）。注意：手机端拉取类功能同样需要手机自身的网络能访问 api.bgm.tv。

## 四、常见故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 打开页面提示“连接被拒绝” | 服务空闲自退（设计行为）或从未启动 | 双击“一键打开”；仍不行看第五节 |
| “拉取剧集/进度”失败，提示“网络不可达…” | 系统代理未开（api.bgm.tv 直连被网络阻断） | 打开 Clash（或等其恢复）后**直接重试**；无需刷新页面、无需改参数 |
| 页面显示旧内容 | 极少见（缓存链路已改为 network-first + no-cache） | 直接按 F5（一次普通刷新即可）；仍异常时看日志 |
| 点“一键打开”无反应/闪退 | D 盘未挂载 / Python 缺失 / 端口被占 | 窗口若有错误提示按其说明；查 `服务器日志.txt` |
| 端口 8089 被其他程序占用 | 其他软件占了端口 | `netstat -ano \| findstr :8089` 找到并处理；或临时改用其他端口（见第六节） |
| 同步中心提示“版本不一致” | 页面与服务器版本文件不同（罕见） | 刷新一次页面即可（文案已更新为“刷新页面即可更新”） |

## 五、一键回滚（已演练通过）

**目标**：从 v2.4.3 回到修复前状态（v2.4.2）。

1. 停止服务：任务管理器结束 `pythonw.exe`（或在日志确认其已空闲自退）；
2. 将 `backup_20260914_pre-v243\` 中的以下 3 个文件覆盖回项目根目录：
   - `index.html`
   - `tracker-sw.js`
   - `tracker-version.json`
3. 双击“一键打开”重新启动 → 页面版本显示 v2.4.2 即回滚成功。

**备用方案**：`git revert <对应提交>` 或 `git checkout backup提交 -- index.html tracker-sw.js tracker-version.json`。
演练记录：已在独立目录完成“2.4.3 → 覆盖备份 → 2.4.2 验证 → 恢复 2.4.3”全流程，见验证记录 E8。

## 九、假设与限制（如实声明）

- 验证基于 Chromium 系浏览器（Chrome）与 Windows 环境；未覆盖 Firefox/Safari 与其他操作系统。
- 网络场景验证以本机真实环境 + 请求拦截模拟为主；未物理拔网线测试。
- 云同步（CloudBase/WebDAV）与 Bangumi 账号级功能需用户授权数据；本轮未做真实账号端到端，仅覆盖到 UI 与错误路径。
- “手机端代理”不在本轮范围：手机无代理时拉取会失败（会给出明确提示），需要时手机侧自行配置网络。
