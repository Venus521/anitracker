# 运维交接手册 · 封面拉取机制与兜底（v2.6.0）

> 项目：追迹 AniTracker｜适用版本：v2.6.0+｜更新日期：2026-09-15
> 本文供日常使用与故障排查：先看「一、60 秒上手」，排障看「五、FAQ」与「六、故障排查清单」。

## 一、60 秒上手

1. 双击 `AniTracker追迹-一键打开.bat`（或桌面快捷方式）→ 自动打开 `http://127.0.0.1:8089/index.html`；
2. 首页工具栏点 **「⟳ 补封面」** → 所有缺封面条目自动从 Bangumi 补齐（有进度与结果提示）；
3. 单条补：打开任意条目详情页 → 点 **「⟳ 重拉封面」**；
4. 以后**新增条目会自动带封面**（在线搜索添加自动抓；手动添加/门户导入的会在打开后由启动自愈或点「补封面」补齐）。

## 二、封面是怎么拉取的（机制）

```
① 扫描          cover 字段不是「本地 dataURL」的条目 → 列入补齐清单
                 （空值 / 外链 / 上次失败遗留，一视同仁）
② 取源          有条目ID(bgmId) ──→ GET /v0/subjects/{id} 取官方封面
                 无ID          ──→ 按 原名/中文名/别名组 搜索（最多3个变体）
                                  → 精确匹配优先，包含匹配兜底（只补封面，不改关联）
③ 抓取          直连 ──(6s失败)──→ proxy.cors.sh ──(6s失败)──→ api.codetabs.com
④ 压缩内联      抓到的图 → 画布压缩 96×128 JPEG → dataURL
⑤ 落盘          写入 tr_shows[].cover（localStorage，本地持久化，离线可用）
⑥ 记台账        成功 → at_cover_try[条目]=ok；失败 → 记录时间，24h 内不自动重试
```

**关键设计点（为什么这样设计）**：
- 封面存**本地 dataURL** 而不是外链 → 不依赖任何第三方图床，离线可看、不会裂图、刷新不丢；
- 取源**优先官方 ID**、无 ID 才猜测标题 → 不擅自改动用户的条目关联关系；
- **24h 退避** → 搜不到的条目不会每次打开都反复重试（不打扰、不刷请求）；
- 批量 **420ms 节流** → 对公共 API 保持礼貌。

## 三、按钮与入口速查

| 入口 | 位置 | 行为 | 耗时参考 |
|------|------|------|----------|
| ⟳ 补封面 | 首页工具栏 | 全量批量补齐（跳过 24h 内失败过的） | 每条约 2–5 秒 |
| ⟳ 重拉封面 | 详情页按钮行 | 单条重新拉取（无视退避，立即重试） | 2–5 秒 |
| 关联 Bangumi | 详情页（未关联时） | 关联条目 → 自动补剧集 + 自动补封面 | 5–15 秒 |
| 启动自愈 | 打开应用后自动 | 静默补 ≤6 部/次，离线跳过 | 后台进行 |
| 点此重试自动拉取 | 详情页横幅（无剧集时） | 拉取剧集列表（与封面独立） | 2–10 秒 |

## 四、失败兜底行为（都已验证）

| 场景 | 行为 |
|------|------|
| 断网/离线 | 补封面自动跳过 + 提示「离线跳过 N 部」；界面保留「无封面」占位图（不裂图不空白）；联网后再点即补 |
| 接口超时/限流 | 单条 6s×3 跳超时；批量继续下一条；失败记入退避台账，界面不堆积报错 |
| 条目在 Bangumi 搜不到 | 保持占位图（可辨识为非加载失败），记 24h 退避；可手动处理（见第五节） |
| 封面图损坏/解码失败 | 视为抓取失败，同「搜不到」处理 |

## 五、手动处理路径（进阶）

**场景 A：搜不到官方封面的条目**（自制内容、冷门条目）
1. 先尝试「关联 Bangumi」找到更准确的条目名后「重拉封面」；
2. 仍然没有 → 接受占位图（设计上可辨识、不报错）。

**场景 B：想手动指定一张网络图片当封面**（高级，浏览器控制台）
```js
// 打开应用后，在浏览器控制台执行（引号内换成图片直链）：
(async () => {
  const s = bySid(curSid);                    // 先在界面打开目标条目详情
  const r = await fetch('https://图片直链.jpg');
  const b = await r.blob();
  const du = await new Promise((res) => { const im = new Image();
    im.onload = () => { const c = document.createElement('canvas');
      c.width = 96; c.height = 128; c.getContext('2d').drawImage(im, 0, 0, 96, 128);
      res(c.toDataURL('image/jpeg', 0.72)); }; im.src = URL.createObjectURL(b); });
  s.cover = du; save(); renderDetail(); toast('封面已手动更新');
})();
```
> 说明：不熟悉控制台请忽略此法——日常场景用「补封面/重拉封面」已覆盖 99% 情况。

**场景 C：离线导入外部备份的封面** —— 正常路径：同步中心 → 导入数据（`tr_shows` 中的封面 dataURL 会一并恢复）。

## 六、FAQ

1. **为什么以前《老友记》没有封面？** 四条添加路径里三条不取封面，且「关联 Bangumi」也不补封面（详见《01-封面缺失诊断报告》）。v2.6.0 起全路径覆盖。
2. **封面存在哪？会不会丢？** 存在本机浏览器 localStorage（`tr_shows[].cover`，dataURL）。刷新/重启/断网都不丢；换浏览器或清空站点数据才会丢 → 用「同步中心 → 导出全部数据」做定期备份即可。
3. **手机上能看到封面吗？** 云同步（账号云同步）会把含封面的数据同步到手机；也可用 GitHub Pages 版（需推送仓库更新）。同网段访问 `http://电脑IP:8089` 亦可。
4. **点「补封面」要多久？** 每条 2–5 秒；100 条约 5–8 分钟（有进度提示，可以放着跑）。
5. **点了没反应？** 看三条：①网络是否可用（页面右下 toast 会有提示）；②条目是否已在 Bangumi 收录（搜不到的会保持占位）；③是否刚失败过（24h 退避，等次日或对单条用「重拉封面」）。
6. **会把我的进度/标记弄乱吗？** 不会。补封面只写 `cover` 一个字段，不动剧集、状态、评分、历史。
7. **深色/浅色怎么切？** 顶栏 ☀/☾ 按钮，选择会记住。
8. **怎么恢复旧版界面？** 见《02-修复与美化说明》第六节（备份覆盖或 git revert，均已演练）。
9. **封面能更清晰吗？** 当前为 96×128 缩略图（体积考虑）；如需高清化可作后续迭代项。
10. **为什么有个条目一直显示「无封面」占位？** 它可能确实搜不到（自制/冷门/无收录）；占位图是「诚实状态」而非故障。

## 七、故障排查清单（按顺序）

1. 首页能否打开？不能 → 跑 `AniTracker追迹-一键打开.bat`（服务器 15 分钟空闲自退，属正常设计）；
2. 点「补封面」后是否出现进度 toast？出现 → 正常在跑；不出现 → 先在同步中心确认页面版本行显示「v2.6.0 · 一致」；
3. 部分条目补不上 → 检查该条目详情页：「数据源」是否有 Bangumi 条目号；没有 → 先「关联 Bangumi」再重拉；
4. 全部条目都补不上 → 大概率网络（api.bgm.tv / lain.bgm.tv 不可达）→ 换个网络/稍后重试；控制台（F12）Network 看 `api.bgm.tv` 请求状态；
5. 界面异常 → 先 Ctrl+F5 强刷；仍异常 → 用备份回滚（见 02 文档第六节），再把现象反馈给维护方。

## 八、维护者备忘（改动须知）

- 改完 `index.html` 必须：① `python 同步双入口.py`（同步 ani-tracker.html）；② 版本号两处一起改（AT_VERSION/AT_BUILD + tracker-version.json）；③ 跑 `运行回归测试.bat`（19 项应全绿）；
- 回归测试自带模拟 Bangumi API（`tests/mock-bgm-api.js`，含封面端点与故障注入），不出网也不碰真实账号；
- 封面自愈相关代码锚点：搜索 `coverHeal` / `cacheCover` / `at_cover_try` / `COVER_PH_L`。
