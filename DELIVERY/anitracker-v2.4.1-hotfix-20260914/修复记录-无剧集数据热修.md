# 修复记录：详情页「无剧集数据 / 全部标记过了 / 统计全 0」（用不了）· v2.4.1 热修 · 2026-09-14

## 一、现象（用户截图）

打开某条目的详情页：统计卡「已看 0 / 回看 0 / 未看 0 / 进度 0%」、来源覆盖「无剧集数据」、横幅「✓ 本作集全部标记过了」、剧集区空态「没有匹配的集（换筛选/关键词试试）」——三者互相矛盾，条目完全无法标记进度。

## 二、根因（代码级确认）

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| 1 | 「B站追番导入」创建的条目**没有 total/eps 字段** | syncFromPortal 的 shows.push | eps=[]、total=0 的空条目 |
| 2 | 「手动添加」总集数留空时 total=0、eps=[] | manualAdd | 同上（属正常输入，但详情页没有后续路径） |
| 3 | 空数据被误判为「全部标记过了」 | renderDetail 的 nextBtn 分支：nextUnwatched 在空列表上返回 null | 误导性横幅，看起来像「用完了」 |
| 4 | 网格空态不区分「没数据」与「筛选无匹配」 | renderGrid | 误导提示 |
| 5 | 关联 Bangumi 后**不会自动拉取剧集列表** | assocPick 只写 bgmId | 即使关联了，条目仍是空的 |

在线搜索添加路径（bgmAttach）本身有保护：拉取失败/无剧集会报错不入库，不受影响。

## 三、修复内容（v2.4.1 · build 20260914c · SW 缓存 anitracker-v5）

1. **新增 `bgmPullEpisodeList(sid)`**：从 bgmAttach 提取「拉取并规整剧集列表」为共用函数（搜索添加、关联补齐共用同一条数据管线）。
2. **关联后自动补齐**：`assocPick` 关联成功后，若条目无剧集数据则自动调用 `bgmFillEpisodes(s)` 拉取剧集并填充，补齐后立即可标记进度。
3. **空数据详情页引导**（原误导文案全部替换）：
   - 横幅改为可点击：「⚠ 此条目还没有剧集数据——点这里自动拉取（已关联 Bangumi），或用「✎ 编辑集数」手动补」；
   - 来源覆盖行追加「关联 Bangumi 补齐剧集 ›」入口（未关联时打开关联搜索，已关联时直接补拉）；
   - 剧集区空态区分：「暂无剧集数据——点上方横幅一键拉取…」与「没有匹配的集（换筛选/关键词试试）」。
4. **添加/导入提示**：手动添加 0 集时 toast 追加「打开详情页可一键拉取剧集」；B 站导入完成提示追加指引。
5. **版本与缓存**：AT_VERSION 2.4.1 / AT_BUILD 20260914c；tracker-version.json 同步；Service Worker 缓存 anitracker-v4 → v5（确保客户端强刷前也能拿到新版）。
