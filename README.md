# AniTracker 追迹 - 完整交付报告

## 一、项目概述

AniTracker（追迹）是一个基于 Web 的番剧追剧管理工具，具备以下核心功能：
- 番剧列表管理
- 集数进度标记
- 灌水/半原创集识别
- 类型自动分类（漫改/TV原创/半原创）
- Bangumi 数据同步
- Filler Guide 灌水池校准
- WebDAV 云同步

## 五、使用说明

### 5.1 基本操作

1. **添加番剧**：点击右上角 ＋ → 输入番名搜索 → 选择 Bangumi 结果
2. **标记进度**：点击集数按钮切换状态
3. **筛选类型**：点击筛选按钮按类型过滤
4. **校准灌水**：在番剧详情页点击"校准灌水池"

### 5.2 高级功能

- **Bangumi 同步**：设置 → 粘贴 access_token
- **云同步**：设置 → 配置 WebDAV 地址
- **数据备份**：设置 → 导出全部数据

## v2.9.0（2026-09-24）· AI 结果导入

**解决什么**：v2.8.0 的 Filler 数据集只有 212 部（animefillerlist.com 全量），
**新番 / 冷门番依然查不到**，只能手动一集一集标。任何第三方数据集都追不上新番更新速度。

**方案**（用户提出）：先问 AI，再把 AI 的回答整段贴给项目。

**用法**：详情页 `✧ AI 结果导入` → `看看要 AI 怎么说`（自动生成提问话术）→ 把 AI 回答整段贴回 → `预览识别` → `写入`。
不用整理格式。

**能认的写法**（实测全过）：`1-10集为漫改，11-15集是TV原创，16集半原创` /
`TV原创：11-15, 23, 45-47` / `1,2,3集是原创` / `第 1、2、3 集是原创；第4集漫改` /
`ep1-5 manga canon, ep6 filler` / `原创：45-47 半原创：50` / `1~5集漫改`。
中英混排、全角半角、有无「第/集/话/ep」都认。

**冲突策略**：AI 粘贴的**优先**，覆盖自动校准；集级来源标为「AI 导入」。
但**你真正手改过的集不会被覆盖**。

**容错**：能认几条认几条，认不出的原样列出、不阻塞写入；纯叙述句静默忽略；
超范围集号预览时警告、写入时丢弃。

**实现**：新增 `at_ai_paste` 存储层（独立于自动抓取缓存，优先级最高）；
`srcInfoOf` 新增 `by:'ai'` 判定分支；解析器 `AT270.aiParse` 用「子句就近归属」
（逗号切子句 → 本子句有词用自己的 → 没有继承前句 → 前句也没有才向后借）。

**测试**：新增 `tests/ai-import-e2e.js`（12/12 PASS，含解析器 8 组单元 + 详情页真实交互）；
主回归 19/19 PASS；双入口字节一致。
详见 `DELIVERY/anitracker-v2.9.0-ai-import-20260924/`。

## v2.9.1（2026-09-24）· 同步精简总开关

**解决什么**：用户反馈「同步还是很累赘」（界面太重、按钮太多）。

**做法**：一个总开关，默认关闭。关闭后隐藏所有 Bangumi / 云同步相关 UI：
- 顶栏 `⇅ 同步` → 改名 **`⇅ 数据`**（保留入口，因为「本地备份」在里面）
- 详情页 `拉取Bangumi进度` / `推送Bangumi` / `关联Bangumi` → 全部隐藏
- 同步中心里的 Bangumi 绑定卡、同步记录台账、账号云同步、高级设置（代理/中继）→ 全部隐藏
- 自动推送变为**完全静默**（`bgmTok()` 返回空 → 15 个推送函数全部空操作，零请求零报错）

**保留**：`本地备份（导出/导入）`——纯文件操作，不碰网络，是真正防丢数据那层。

**开回**：`⇅ 数据` → 展开「已精简的同步功能」→ `重新开启同步功能`。反向同理（高级设置最底部）。

**实现要点**：默认精简（`localStorage.at_sync_off` 无值即精简）；**单点拦截**——
改 `bgmTok()` 一个函数覆盖 15 处调用点，避免改漏；`syncOpen()` 按 `OFF` 三元渲染。

**测试**：主回归 **22/22 PASS**（新增 T10a 默认精简 / T10b 精简面板内容 / T15b 精简态静默）；
AI 导入 12/12 PASS 未退化；双入口字节一致。
详见 `DELIVERY/anitracker-v2.9.1-slim-sync-20260924/`。

## v2.9.2（2026-09-25）· 同步改版：按使用频率分层

v2.9.1 的「精简总开关」是错的解法——它只是把累赘藏起来，不是消除累赘。
本版改为**频率分层**：常用的摆出来、不常用的收起来、一眼能看出状态。

- **顶部一句话状态**：`● Bangumi 已绑定 · 上次同步 1 小时前`，打开就知道什么状况
- **一个主行动按钮**，随状态变：未绑定 →「去绑定 Bangumi」；已绑定 →「立即同步进度」
- **常开档**：本地备份、Bangumi 账号卡
- **折叠档**（默认收起、点开即用、状态会记住）：账号云同步 / 同步记录 / 高级设置
- **详情页**：拉取/推送按钮改为**只在本作真的关联了 Bangumi 时出现**；
  日常按钮（播放/编辑集数/来源校准/AI 导入）排到前面
- 撤掉 `syncOff()` 全局隐藏、`applySyncOff`、`optSyncOn/optSyncOffBtn`；
  顶栏按钮从「数据」改回「同步」；`bgmTok()` 单点拦截移除，同步链路默认可用
- 老用户若留有 `at_sync_off` 标记，首次打开自动清除并恢复完整 UI
