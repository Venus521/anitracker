# 部署与回滚说明（AniTracker v2.3）

## 一、运行方式（默认端口 127.0.0.1:8089）

- **日常使用（零驻留）**：双击 `AniTracker追迹-一键打开.bat` → 按需启动本地静态服务（15 分钟无访问自动退出）并打开 `http://127.0.0.1:8089/index.html?v=随机数`。
- **手动启动（等价命令）**：
  ```
  python 服务器-空闲自退.py --port 8089 --host 0.0.0.0 --dir . --idle 900 --log 服务器日志.txt
  ```
- 直接双击 `index.html` 也能用（云同步 SDK 需联网），但**建议走 8089 或门户**以获得完整功能（搜索/同步的跨域与缓存行为最稳）。

## 二、关键文件清单

| 文件 | 作用 |
|---|---|
| `index.html` | 主应用（v2.3）；与 `ani-tracker.html` 为同内容双入口 |
| `ani-tracker.html` | 第二入口（与 index.html 保持一致） |
| `tracker-version.json` | **版本标识**：页面启动时读取并与内置版本比对（✓ 一致 / 不一致提示强刷） |
| `tracker-sw.js` | Service Worker v3：同源资源全部 network-first（强刷必得新逻辑，离线回退缓存） |
| `cloudbase-sync.js` | 账号云同步模块（含注册入口与同步台账挂钩） |
| `tracker-filler-data.js` | Anime Filler Guide 离线数据集（58 部） |
| `服务器-空闲自退.py` | 本地静态服务器（启动日志会打印应用版本号，如 `(app v2.3.0)`） |
| `AniTracker追迹-一键打开.bat` | 一键入口 |
| `backup_20260914_pre-v23/` | **v2.3 改动前的原版备份**（回滚用） |

## 三、缓存/版本对齐机制（怎么保证不是"旧页面"）

1. 入口沿用 `?v=随机数`（启动器自动追加）+ 服务器 `Cache-Control: no-cache`。
2. SW 升级 v3：所有本地资源（含 JS）network-first，刷新即最新。
3. 页面与 `tracker-version.json` 双向校验，在「同步中心」底部显示版本行。
4. **发布新版本 SOP**：改 `index.html` 中 `AT_VERSION` → 同步改 `tracker-version.json` → 复制 index.html 到 ani-tracker.html → SW 缓存名 +1。

## 四、凭据与环境配置

- **Bangumi**：应用内「同步中心 → Bangumi 账号」粘贴 access_token（存本机浏览器 `at_bgm_token`）。生成入口：https://bgm.tv/settings/services →「API 访问令牌」。
- **账号云同步**：应用内直接注册/登录（CloudBase 托管；用户名 + 密码 ≥8 位）。
- **环境变量**：无，全部配置位于浏览器本机。

## 五、回滚到上一版本（步骤已演练）

1. 数据兼容性：v2.3 只新增增量字段（`e.src`/`e.srcNote`/`at_sync_log` 等），旧版打开不会崩、不会丢数据。
2. **文件级回滚（最快）**——在项目目录执行：
   ```powershell
   Copy-Item backup_20260914_pre-v23\index.html index.html -Force
   Copy-Item backup_20260914_pre-v23\ani-tracker.html ani-tracker.html -Force
   Copy-Item backup_20260914_pre-v23\cloudbase-sync.js cloudbase-sync.js -Force
   Copy-Item backup_20260914_pre-v23\tracker-sw.js tracker-sw.js -Force
   Copy-Item backup_20260914_pre-v23\服务器-空闲自退.py 服务器-空闲自退.py -Force
   Remove-Item tracker-version.json -ErrorAction SilentlyContinue   # 或改回旧版本号
   ```
3. 重启服务：结束占用 8089 的 python 进程（或等其空闲自退），再双击一键打开.bat。
4. **git 回滚（更稳）**：
   ```
   git log --oneline          # 找到 v2.3 提交
   git revert <sha>           # 或 git checkout <上一提交> -- index.html ani-tracker.html tracker-sw.js
   ```
   随后同样重启服务。
5. 验证回滚结果：同步中心版本行显示旧版本；列表/详情正常；旧版没有「来源筛选」属预期。

## 六、已知边界（如实说明）

- Bangumi 接口有限流：应用内置节流（写 ≥1.1s 间隔、读 ≥0.35s，429 自动退避重试）。批量操作请等进度提示完成。
- 官方 API 不支持"删除收藏"：回滚能把推送过的"看过"标记与状态恢复原值；由本次推送"新建"的收藏无法恢复为空（界面会注明）。
- `服务器-空闲自退.py` / `*.txt` 日志在 `.gitignore` 中（不入 git），回滚请用 `backup_20260914_pre-v23/` 目录。
- 本版本未做多用户/公网部署（单机单人场景）。

## 启动器修复记录（2026-09-14）

**症状**：双击「AniTracker追迹-一键打开.bat」黑框一闪而过、无反应（服务未启动、页面未打开）。

**根因**（两层问题叠加）：
1. 原批处理为 UTF-8 编码且中途 `chcp 65001`：在中文系统（代码页 936）下触发 cmd 批处理重读错位——`if %errorlevel% equ 0` 被读成 `0 equ 0`、`set /a` 被截断，服务启动命令根本未执行；
2. 修正编码后仍有第二层：批处理行内的中文文件名（服务器-空闲自退.py）在代码页转换中变成乱码字节，pythonw 报 "can't open file" 后静默退出。

**修复方案**：
- 新增 `server.py`（ASCII 文件名包装器：由 Python 以 Unicode 正确解析中文文件名，并自动补默认参数 `--log 服务器日志.txt`）；
- 「AniTracker追迹-一键打开.bat」改为 GBK 编码、不再切换代码页，所有执行性命令行全部 ASCII（中文只保留在提示文字），标签化结构重写，步骤提示 [1/3]→[3/3]，失败时窗口停留显示原因。

**验证**（2026-09-14 19:14-19:17）：
- 936 环境：冷启动 4.6s、热路径 3.3s，端口就位、页面可访问；65001 环境同样通过；
- 真实运行演示：日志出现 `GET /index.html?v=23810` 及后续全部资源请求（浏览器成功打开页面）。

**回滚**：原版批处理在 `backup_20260914_pre-v24/AniTracker追迹-一键打开.bat`；`server.py` 为独立新增文件，删除不影响其他入口。
