## 一、运行方式（默认 127.0.0.1:8089）

- **日常使用（零驻留）**：`C:\Users\Venus\DeskBox\启动方式\` 里的追迹入口 → 按需启动本地服务并开页面。
- **手动启动（等价命令）**：
  ```
  python 服务器-空闲自退.py --port 8089 --dir . --idle 900 --log 服务器日志.txt
  ```
  **host 缺省 127.0.0.1（本机全功能）。** 唯一需要 `--host 0.0.0.0` 的场景是手机局域网下载 APK
  （`手机安装入口.py` 自动带）——该模式下服务器只服务 APK 分发与页面资源白名单，目录列表关闭，
  `.git`/keystore/日志/源码一概 404，中转端点要求同源（v2.51.0 防护，黑盒 12 项验证过）。
- 双击 `index.html`（file://）可用：豆瓣封面/联想走云函数，账号云同步走不通（网关 CORS 名单）。

## 二、发布流水线（详见 readme.md 第三节，顺序不可换）

1. 改 `index.html`（唯一源；双入口由 pre-commit 钩子或 `python 同步双入口.py` 跟上）。
2. `python 发版.py X.Y.Z --note "…"`——六处一次改齐；**失败自动回滚六处**（备份在
   `_archive/发版备份_时间戳/`），同版本拒绝重发（versionCode +1 增量，防双跳）。
3. 跑门禁：`运行回归测试.bat`（26 条串行全集）至少 `node tests/phone-look.js` + `node tests/run-regression.js`。
4. `python mobile-shell/build-apk.py` → `python mobile-shell/发布到云端.py "说明"`（三路一次发）。
   公网验证失败**自动回传旧清单**（发布前快照在 `_archive/线上备份_发布_*/`）；code 落账在验证全过
   之后，失败不记账、下次发布复用该 code 覆盖——坏包自愈。
5. 改云函数后：`tcb fn deploy douban-relay-node --force --httpFn --path /douban-relay
   --dir cloud-functions\douban-relay-node --runtime Nodejs20.19 -e cloud1-d7gsn5t0w6407b963`
   （末尾 Path is used 报错无害；curl 三模式验证）。

## 三、回滚

- **git 回滚（首选）**：`git log --oneline` 找版本收口提交 → `git checkout <sha> -- .` 或 `git revert`。
  发版/发布前的文件级备份在 `_archive/发版备份_*` 与 `_archive/线上备份_发布_*`。
- **线上内容包回滚**：手机端读 `/app/web.json` 的 code 指针。把旧清单（`_archive/线上备份_发布_*/web.json`）
  重新 `tcb hosting deploy` 到 `/app/web.json` 即回到旧包；坏包文件留在 `/app/web/<code>/` 无害。
- **APK 路回滚**：同理回传旧 `/app/version.json`；APK 文件名带版本号永不互相覆盖。

## 四、凭据与环境配置（v2.51.0 现状）

- **Bangumi**：已于 v2.17 退役，无配置。
- **账号云同步**：应用内注册/登录（CloudBase 托管，用户名+密码）；豆瓣 Cookie 云端加密存（忘密码=重粘）。
- **TMDB / AI key**：可选进阶，用户自配（明文本机 localStorage，已被 SECRET_KEY_RE 剔出导出/云同步）。
- **必经路径零配置**：封面/联想/时长全部免配置可用（TMDB 密钥是可选进阶——用户令 v2.29.1，长期有效）。
- **发布凭据**：本机 `tcb` CLI 登录态，脚本无硬编码密钥。
- **环境变量**：`AT_DB_SUGGEST_BASE`/`AT_DB_RELAY_BASE`（门禁摘出站用）、`AT_CHROME`/`AT_PY`
  （换机跑门禁）、`AT_ANDROID_BUILD`/`AT_SHELL_SRC`/`AT_SHELL_BUILD`（换机打 APK）。
