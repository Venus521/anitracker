# 排版重设计方案与实施回滚（追迹 AniTracker）· 2026-09-14

> 基于《排版-审计与差距矩阵》的判定：**需要体系级重设计**。本方案只换「骨架」（刻度/网格/组件规则），**不换皮肤**（沿用暖色体系与字体对）；覆盖全部高优先级不满足项（R1/R3/R5/R9/R11）与规则性差距（R2/R7/R8/R10）。
> 设计方法论：瑞士网格（Müller-Brockmann）的数学纪律——4pt 基准、刻度锁定、左对齐、单强调色、无装饰；适配点：强调色沿用应用金棕 `#b08d4f`、展示字体沿用衬线栈（品牌上下文更强，按规范「有更强品牌语境时允许适配并说明」）。

## 一、设计原则（五条）

1. **4pt 基准**：一切间距、高度、圆角皆为 4 的倍数；
2. **刻度锁定**：字号/行高/间距/圆角只允许使用下表取值，新需求先扩刻度、再使用；
3. **排版即装饰**：用层级、对齐与留白表达结构，不增加装饰元素；
4. **对齐纪律**：文本左对齐；数字右对齐或等宽；任何元素贴同一基线网格；
5. **单强调色**：全站仍只有金棕一个强调色；状态色（danger）只用于错误。

## 三、网格与对齐

- 4pt 基线；单列 560 容器；列表行内容格：`缩略图 44 | 主体（弹性） | 右侧数字（等宽右对齐）`；
- 统计数字：`.num` 使用 `font-variant-numeric: tabular-nums`，衬线；
- 所有分区标题贴左边距、下衬 1px 线；所有卡片内边距 16；
- 文本与图标光学对齐（图标 1px 下沉基准）。

## 五、响应式规则

| 断点 | 规则 |
|---|---|
| ≤559px（含 320） | 单列全宽；边距 20；弹层 `min(92vw, 520px)` |
| 560–879px | 边距 24；容器仍 560 居中（阅读宽度优先） |
| ≥880px | 同上 + 弹层双列可用（列表+详情并排仅用于弹层，不改变主流程）；无横向滚动为硬约束 |

禁止：任何屏宽出现横向滚动；触控目标缩小；等比缩小桌面布局（窄屏必须信息重排）。

## 六、导出规则（本期非目标）

## 八、实施步骤（应用到应用时执行）

1. **注入令牌**：将第二节全量写入 `:root`（与现有颜色变量并列）；不改变任何现有规则（零视觉变化提交）；
2. **组件替换**：按第四节规则逐组件替换（顶栏→列表→详情→同步中心→搜索），每组件替换后跑一次布局自检脚本（三档宽度无溢出）；
3. **全量映射**：按第七节映射表批量替换 rest 的散值（脚本执行，双轮扫描至「刻度外计数=0」）；
4. **清理**：移除内联排版样式（白名单：动态进度条宽度）；
5. **验收**：跑《排版-验收测试与计划》全量用例；git 单提交（附审计前后对比数据）。
   - 预计影响：仅 `index.html`；CSS 增量 ≤8KB；无 JS/数据改动。

## 九、回滚方案

- **触发条件**：验收任一 P0 用例失败且 30 分钟内不可修复；或线上出现任何功能性回归；
- **操作**：`git revert <排版提交>`（或从 `backup_*` 目录恢复 index.html）→ 强刷（SW network-first 即时生效）；
- **演练**：已在本机演练「恢复备份 → 页面回到旧版样式 → 功能正常」（见验收记录）；
- **数据**：本方案不触碰任何数据（localStorage 零改动），回滚无残留。
